## ❌ ГЛАВНАЯ ОШИБКА — неправильная последовательность блокировки

### Что мы сделали

```bash
fastboot erase efisp         # ✅ Правильно
fastboot oem lock            # ❌ НЕДОСТАТОЧНО
```

Результат: `Device unlocked: false`, Verity включен, но Google Play Protect всё равно отказывал («Lock bootloader to fix issue»), а телефон потом вообще стуck в Fastboot.

### Что нужно было сделать

Правильная последовательность после **неофициальной (эксплойт) разблокировки**:

1. **Прошить полностью стоковую ОФИЦИАЛЬНУЮ прошивку** (никаких Magisk, TWRP, кастомов). Убедиться что система грузится.

2. **Перезагрузиться в fastboot и выполнить:**
   ```bash
   fastboot erase efisp
   ```
   Эта команда удаляет метку эксплойт-разлочки.

3. **БЕЗ загрузки в систему** — ещё раз прошить ту же официальную прошивку через **MiFlash с параметром `clean_all_and_lock`** (clear_all_lock).

4. Только после шага 3 bootloader реально чистый под Verified Boot.

### Почему `fastboot oem lock` сам по себе не работает

Эксплойт-разлочка оставляет следы в системных разделах (не только в RPMB и efisp). `fastboot oem lock` меняет только lock state, но не чистит эти следы. Google Play Protect и Verified Boot при загрузке видят эти остатки и отказывают.

Только повторная прошивка под флагом `clean_all_and_lock` переписывает все разделы заново и устанавливает lock state атомарно, без «грязных» следов.

### Источник информации

Мастер из сервиса «Mobil Hafiz», подтверждено практикой — именно он успешно выполнил эту последовательность на других телефонах с pandora.

## 🔧 Chip-off ремонт — последняя надежда

Если программные методы не сработали (как у нас — EDL закрыт, Firehose loaders недоступны, UFS-ISP padов нет), остаётся физический ремонт.

### Как это делается

1. **Разборка телефона** — снятие экрана, батареи, материнской платы
2. **Выпайка UFS BGA-чипа** — инфракрасная паяльная станция, ~230-250°C
3. **Чистка и reballing** — старые BGA-шарики удаляются, напаиваются новые через трафарет
4. **Прошивка в программаторе** — UFSPROG / Medusa Pro II / EasyJTAG читает и перезаписывает всю NAND напрямую
5. **Напайка обратно** — повторный reflow с новыми шариками
6. **Сборка телефона**

### Стоимость (на 2026 год, Азербайджан/СНГ)

| Устройство | Цена chip-off |
|------------|---------------|
| Xiaomi флагман (8 Elite / UFS 4.0) | 250-400 AZN (~$150-250) |
| Средний класс | 150-250 AZN |
| Если UFS/CPU повреждён — замена чипа | 500-1000+ AZN |

### Риски (которые нужно принять)

**Что ухудшается после chip-off:**

1. **BGA-шары** — заводская пайка делается в вакууме под давлением. Ручная пересадка = чуть хуже контакт. Через 1-2 года термоциклы могут дать микротрещины.

2. **NAND-ячейки** — повторный нагрев чипа до 230-250°C ускоряет деградацию ячеек. Теряется заряд быстрее.

3. **Pad'ы на материнке** — при неаккуратной выпайке можно «сорвать» медный pad. Тогда следующий ремонт сложнее.

### Срок жизни

| Период | Что ожидать |
|--------|-------------|
| 0-6 месяцев | Гарантия мастера — если что, переделает |
| 1-2 года | Почти наверняка проблем не будет |
| 3-4 года | Может начаться: случайные ребуты, медленная работа, «device storage error» |
| 5+ лет | Вероятно телефон доживёт, но не факт |

**Сравнение:** заводской телефон живёт 5-7 лет активной работы (TBW ~600-1000 ТБ записи UFS 4.0). После chip-off — 3-5 лет реалистично.

### Как продлить жизнь после chip-off

- **Не грей телефон** — игры с макс. графикой + зарядка 120W в жару = термоциклы = главный враг пайки
- **Не роняй** — удар может добить ослабленные шары
- **Через месяц проверь скорость UFS** в A1 SD Bench или CPDT (норма для UFS 4.0: ~3000+ МБ/с чтение). Запиши базовую линию.
- **Через полгода и год повтори тест** — если скорость упала более чем на 20%, пайка начинает деградировать

### Что спросить у мастера

1. **Какая гарантия на пайку?** (норма 3-6 месяцев, у «Mobil Hafiz» — 6)
2. **Chip-off или ISP?** (ISP = припайка проводов без выпайки = риск меньше, но на новых Xiaomi редко возможен из-за отсутствия тестпадов)
3. **Есть ли инфракрасная станция + трафареты именно под твой UFS?** (не фен — фен даст холодную пайку)
4. **Что если NAND окажется мёртв?** (замена UFS = в 2-3 раза дороже)

## 🧪 Что мы пробовали и почему не сработало

Полный список попыток 15-20 октября (см. [README.md](README.md) для деталей):

| Метод | Результат | Почему не сработал |
|-------|-----------|-------------------|
| `fastboot oem device-info` | OK | Диагностика работала, но lock state уже сломан |
| Mi Flash clean_all_and_lock | ❌ | Телефон не входит в EDL (стуck в Fastboot) |
| EDL кабель (COM port) | ❌ | SM8850 требует подписанный Firehose loader |
| TWRP boot (fastboot boot) | ❌ | Verified Boot блокирует неподписанные образы |
| GBL exploit (gbl_efi_unlock.efi) | ❌ | efisp стёрт + нельзя писать при locked + патч закрыл дыру в HyperOS 3.0.304+ |
| UnlockerBL_8EG5_v2 (повторно) | ❌ | Требует разблокированный загрузчик для записи efisp |
| Публичные Firehose loaders | ❌ | Для SM8850 (Snapdragon 8 Elite) не опубликованы |
| UMcrew / @three_tools_gsm | Не пробовали | Коммерческие сервисы, работают с приватными ключами — потенциально дорого |

**Вывод:** для **CNXM ROM (Китай) + заблокированного SM8850 + стёртого efisp** публичных программных методов не существует. Либо коммерческий сервис с приватными ключами Xiaomi, либо chip-off.

## 🚨 Правила на будущее

### Перед любыми операциями с загрузчиком

1. **Полный бэкап всех разделов** через TWRP пока загрузчик разблокирован:
   ```bash
   # В TWRP:
   dd if=/dev/block/sda of=/sdcard/full_backup.img bs=4M
   ```

2. **Отдельно сохрани критические разделы:**
   - `boot_a`, `boot_b`
   - `vbmeta_a`, `vbmeta_b`
   - `recovery_a`, `recovery_b`
   - `efisp` (ВАЖНО — содержит метку разблокировки)
   - `rpmb` если возможно

3. **Сохрани dynamic token** (`fastboot oem get-token`) — пригодится.

### Перед блокировкой загрузчика

1. **ОБЯЗАТЕЛЬНО** читай [правильную последовательность выше](#что-нужно-было-сделать)
2. **НИКОГДА** не используй `fastboot oem lock` сразу после `fastboot erase efisp`
3. Убедись что у тебя есть **официальная стоковая прошивка** нужной версии и работающий **MiFlash с параметром clean_all_and_lock**
4. Знай что процесс сотрёт все данные — забэкапь всё что нужно

### Если телефон стуck в Fastboot

1. **Не паникуй, не пробуй случайные команды** — каждая `fastboot erase` или `fastboot flash` может ухудшить ситуацию
2. **Собери диагностику:**
   ```bash
   fastboot getvar all > diagnostic.txt
   fastboot oem device-info
   ```
3. **Проверь можно ли войти в EDL** (разные комбинации клавиш для разных моделей)
4. **Если EDL закрыт** — программные методы бесполезны, иди в сервис
5. **НЕ отдавай первому попавшемуся мастеру** — спроси опыт именно с твоей моделью

### При выборе сервиса

Задай вопросы:
- Делали ли они **именно эту модель** раньше?
- Есть ли у них **инфракрасная паяльная станция** (не фен)?
- Какая **гарантия на пайку**?
- Что если **UFS/CPU окажется повреждён** — сколько будет стоить замена?
- Можно ли попросить **ISP вместо chip-off** (меньше риска)?

## 📎 Приложение: что в итоге установлено

- **Прошивка:** HyperOS 3 stable, OS4.0.2.0.XBLCNXM (Android 17, патч 2026-10-01)
- **Bootloader:** заблокирован (verified boot зелёный)
- **Why HyperOS 3 а не 4:** эксплойт разлочки для HyperOS 4 не существует на момент 2026-10-21, поэтому мастер поставил HyperOS 3 — на случай если нужна будет повторная разлочка через существующий эксплойт для HyperOS 3

- **На HyperOS 3** — можно через UnlockerBL_8EG5_v2, но:

  - Опять сломается MyGov (гос. приложение)
  - И если **повторно блокировать** — не повторяй нашу ошибку, следуй правильной последовательности!
- **На HyperOS 4** — пока невозможно (эксплойт не опубликован)
